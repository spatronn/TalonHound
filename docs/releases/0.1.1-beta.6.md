# TalonHound v0.1.1-beta.6

Bug-fix beta for MCP API key creation in the Administration UI.

## Fixes

### API Keys — MCP owner dropdown

- **MCP Read / MCP Analyst key creation no longer fails with `owner_public_id must be a valid UUID`.** The Create API Key owner `<select>` read `user.public_id`, but `GET /api/users` exposes the stable public UUID as `id` (via `toPublicUser`). With `value={undefined}`, the browser submitted the visible label (for example `safa@safa.com (admin)`) instead of a UUID.
- The owner option value is now the users-API public UUID (`user.id`), while the label remains `username (role)`.
- Form state stays aligned with the visible selection: MCP profiles start on the explicit “Select owner…” placeholder; switching away from MCP clears owner; switching between MCP profiles keeps a still-valid UUID and drops stale/label values.
- Backend UUID validation and owner RBAC intersection are unchanged.

## Notes

- This is a beta prerelease.
- No database migration is introduced by this release (latest migration is unchanged from v0.1.1-beta.5).
- Existing TalonHound beta users can upgrade using the project's supported upgrade mechanism.

- Fresh install: `sudo ./installation.sh`
- Upgrade: `sudo ./installation.sh --upgrade` (or `--upgrade-to 0.1.1-beta.6`)
- Official images and digests are recorded in `release-manifest.json`

See `docs/deployment.md` and `docs/upgrade.md`.
