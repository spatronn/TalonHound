# TalonHound v0.2.0-beta.12

Feature beta introducing the **Threat Library** — import threat reports, extract and review their IOCs, and turn approved indicators into IOCs — together with more accurate IOC metadata and history, lower database write load, and faster IOC browsing.

The minor version moves to 0.2.0 because this beta adds a new product area (Threat Library, its worker service, and database migrations 019–036) on top of the 0.1.1 beta line. All changes are backward compatible; existing IOC, feed, API and MCP behavior is preserved except where noted as a fix.

## Added

### Threat Library
- Import threat intelligence reports from a URL, a PDF upload, or a portable THIB 1.0 bundle. Re-submitting an already imported URL or PDF resolves to the existing report instead of creating a duplicate.
- Deterministic IOC extraction from HTML, PDF and text, including structured IOC tables (wrapped hash cells, defanged values, `<br>`-separated rows) without needing AI.
- Optional AI analysis (local Ollama or another configured provider; nothing is sent until an administrator enables one) for summaries, entities, relationships and report tags, with bounded output, long-running model support, and a configurable limit on concurrent analyses.
- Report review workflow: Overview, Indicators, Entities and Source tabs; a read-only indicator drawer; Approve / Context only / promote decisions; **Create IOCs** that turns approved indicators into IOCs and reports per-row results, including existing IOCs.
- Server-side search, pagination and sortable columns for the report list; source publication date extraction (shown as Published), kept separate from the TalonHound import time.
- Deterministic, editable TLP — the AI model can no longer assign TLP.
- Report tags can be inherited by linked IOCs as effective "Threat Context" tags with provenance, without copying them into the IOC's own tags.
- Explicit job modes: **Retry** recovers failed analyses only, **Refresh extraction** re-applies the current extractor to the stored document without running AI, and **Re-run AI** re-analyzes. Analyst decisions and Create-IOC links survive all of them, and a finalized report reopens for review only when a refresh actually changes what needs review.
- Threat Library actions are recorded in the audit log with the acting user.

### MCP
- `get_ioc_context` returns `threat_context` (Threat Library claims, per-claim occurrences, report summary/entities, relationships) and `derived_infrastructure` for URL IOCs with an IP host.
- New `get_threat_report` tool to drill into a single Threat Library report (paged indicators, entities, relationships).

### IOC Search and enrichment
- Rolling relative dates in the IOC Search DSL, e.g. `created_at after "now-5d"` (units `m`/`h`/`d`/`w`), plus an `imported_at` alias. Published Feeds using a rolling window are always regenerated in full so their membership stays correct.
- VirusTotal URL Web Analysis (brand, behavior tags, HTTP details, redirects, outgoing links) shown in IOC Details and MCP from already-stored enrichment, with no extra API calls.

## Improved

### Threat Library extraction accuracy
- Reports with a publisher-declared IOC section list only those indicators in Indicators. Values that appear only in the narrative go to review instead of being counted as declared IOCs.
- Observable types come from source semantics instead of syntax alone: dotted identifiers, relative paths, file names, IPv4 prefixes carved from hostnames, and hashes embedded in URLs are no longer misread as domains, URLs, IPs or standalone hashes.
- Completeness diagnostics flag explicit IOC table rows that were dropped during extraction.
- AI roles, relationships and report tags are checked deterministically against the source; report tags favor the most salient context, and automatic MITRE ATT&CK mapping was removed after it failed quality evaluation.

### IOC metadata and history
- IOC sources reflect every per-feed membership, not just the feed that first created the IOC. Classifications use the canonical effective set (manual, feed and analyst), and report context is no longer presented as an IOC tag.
- IOC History shows one "Imported from Feed" event per feed, dated when TalonHound imported the IOC from that feed rather than the feed's own first-seen time. Re-sightings no longer add history entries.
- ThreatFox source observations keep first/last-seen separate from last-changed, and fixed TTLs extend from the source's last observation.
- Exact IOC lookups (`lookup_ioc`, `bulk_lookup_iocs`, `get_ioc_context`, API) resolve proven MD5/SHA1/SHA256 aliases of the same file, and IOC search returns real metadata.

## Fixed
- Bulk "add classification" now preserves existing manual and analyst classifications instead of replacing them.
- Published Feeds: failed generations clean up the chunk files they wrote (leaked files previously filled the disk), an hourly orphan GC acts as a safety net, hash feeds no longer fail on a STIX item-count mismatch, and repeated failures back off (shown on the feed API).
- File artifacts keep VirusTotal results, Threat Context and analyst relations across hash-alias merges.
- A fresh database now migrates successfully on the first attempt (seeded sequences restored).
- UI: Analyst Intelligence stays last in IOC Details, Deep Search pagination controls stay in sync, and Web Analysis URLs are not clickable.

## Performance and Reliability
- Fewer IOC writes: unchanged confidence, status, expiry, fingerprints, evidence, tags, file-artifact flags and feed source-state snapshots are no longer rewritten on every feed re-sight, which significantly reduces database WAL and I/O.
- CERT and PhishTank sync now detect new IOCs by comparing against stored feed memberships instead of rewriting multi-megabyte checkpoints.
- IOC list browsing ranks identities first and groups only the current page, and confidence rows are looked up by primary key.
- IOC statistics are served from the persisted snapshot on startup and fully recomputed once a night, instead of on every restart.

## Compatibility
- **Database migrations 019–036 are included** (Threat Library tables, job modes, report tags, import identity, publication-date provenance, Published Feed failure backoff, IOC source last-seen, file-artifact link repair and index, feed-evidence classification index, seeded-sequence alignment). Run migrations as part of the upgrade; they are additive, and existing data is preserved.
- New service: `threat-library-worker` (shares the backend image). AI analysis is optional and stays off until an administrator configures a provider in Threat Library settings.
- MCP and API changes are additive. No dependency major-version changes; runtime remains Node.js 24.

## Internal
- The watchlist route test's in-memory database now models the alias-aware watchlist queries introduced with hash-alias support, so the per-user status and unstar tests exercise the real query shape again (test-only; no product change).
