# TalonHound v0.2.0-beta.13

Bugfix beta for v0.2.0-beta.12: the integration worker could not start. No database migration, no API contract changes.

All v0.2.0-beta.12 changes (Threat Library, MCP threat context, IOC metadata/history, performance and reliability work) are included unchanged — see the [v0.2.0-beta.12 release notes](https://github.com/spatronn/TalonHound/releases/tag/v0.2.0-beta.12). **Upgrade to v0.2.0-beta.13 instead of v0.2.0-beta.12.**

## Fixed

### Integration worker crash on start
The `talonhound-integration` image in v0.2.0-beta.12 was missing a backend module that the shared IOC expiration code now imports for per-feed IOC History import events. The integration worker exited with `ERR_MODULE_NOT_FOUND` (`iocSourceImportHistory.js`) on every start and restarted repeatedly, so threat feed syncs did not run.

- The integration image now includes the module.
- A new release-critical test simulates the integration image and fails if any static import of a module in it would not resolve, so a missing module is caught in CI instead of at container start.

## Compatibility
- **No database migration.** Schema is unchanged from v0.2.0-beta.12 (latest migration 036).
- Only the `talonhound-integration` image changes in behavior; backend, frontend and proxy are rebuilt with the new version only.
- No API, MCP or dependency changes.

## Validation
- Backend `test:release` 56/56 (including the new integration-image import guard, which fails without the fix and passes with it), `test:migrate` 26/26, `test:sprint-smoke` 187/187, `test:setup-wizard` 40/40.
- Frontend: product-version 11/11, full unit suite 952/952, production build succeeds.
