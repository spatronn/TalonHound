# TalonHound v0.1.1-beta.11

Bugfix beta: reuse a VirusTotal result across exact file-hash aliases. No database migration, no API contract changes.

## Fixed

### VirusTotal exact-hash alias enrichment
Fixed a case where VirusTotal enrichment performed against one exact file-hash alias (for example SHA1) could appear as "VirusTotal enrichment has not been run yet" after TalonHound resolved the same file to its canonical SHA256 artifact — which could prompt an analyst to spend a second VirusTotal request even though the first had already succeeded.

The existing successful VirusTotal response is now reused across proven exact MD5/SHA1/SHA256 aliases of the same file artifact, so a single VirusTotal file lookup is sufficient.

- No new alternate-hash IOC records are created.
- Original IOC source/provenance remains unchanged.
- The alias notice ("Requested SHA1 is a known hash of this SHA256 file artifact.") remains purely informational; Dismiss only dismisses the notice.
- File Information continues to expose known exact hashes (SHA256/SHA1/MD5) and technical metadata.
- Reuse is limited to exact hashes proven to belong to the same file artifact — no fuzzy matching, and no additional VirusTotal request is issued to resolve an alias.

## Compatibility

- **No database migration required.** No schema or data changes.
- No API contract changes. IOC ingestion source, feed membership, published feeds, confidence, and classification semantics are unchanged.
- No dependency version changes. No experimental feature flags are enabled by this fix.

## Validation

- Backend: new `virustotalEnrichmentReuse` regression suite plus VirusTotal enrichment, VirusTotal file metadata, IOC File Information, enrichment-aggregator, file-artifact, hash-normalization, and MCP IOC suites pass. The regression proves a single provider request suffices: an enrichment stored against an exact-hash alias is reused on the canonical IOC (`reused_from_alias`), direct enrichment still takes precedence, identity mismatches and unrelated artifacts are rejected, and failed/not-indexed semantics are preserved.
- Frontend: full test suite passes and the production build succeeds (frontend code is unchanged by this fix).
