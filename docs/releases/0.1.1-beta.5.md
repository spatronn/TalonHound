# TalonHound v0.1.1-beta.5

Bug-fix beta for the MCP `search_iocs` tool, found during live MCP acceptance testing of v0.1.1-beta.4.

## Fixes

### MCP `search_iocs`

- **Structured filters now work.** The `type`, `classification`, and `source` arguments previously emitted invalid `field:value` syntax and always failed with `VALIDATION_ERROR: Unexpected character ":"`. They are now translated into valid IOC Search DSL (`type equals "domain"`, `classification equals "…"`, `source equals "…"`, `type in ("md5","sha1","sha256")` for hashes), reusing the existing IOC search engine — no second search path.
- **Plain-text queries are now useful.** A bare `query` such as `evil.com` (previously `Unknown field`) is treated as a bounded IOC-value search (`ioc contains "…"`). Explicit Search DSL is still supported unchanged, and a broken DSL attempt still surfaces the DSL error (validation is not weakened).
- **Filters may be used without a free-text `query`** (e.g. `search_iocs({ type: "domain" })`); at least one of `query`/`type`/`classification`/`source` is required.
- Tool description/schema now document the accepted DSL and plain-text behavior. See [`docs/MCP.md`](../MCP.md).

Other tools (`lookup_ioc`, `get_ioc_context`, `bulk_lookup_iocs`, `list_ioc_sources`, `import_iocs`), authentication, scopes, rate limits, and audit are unchanged.

## Notes

- This is a beta prerelease.
- No database migration is introduced by this release (latest migration is unchanged from v0.1.1-beta.4).
- Existing TalonHound beta users can upgrade using the project's supported upgrade mechanism.

## Install and upgrade

- Fresh install: `sudo ./installation.sh`
- Upgrade: `sudo ./installation.sh --upgrade` (or `--upgrade-to 0.1.1-beta.5`)
- Official images and digests are recorded in `release-manifest.json`

See `docs/deployment.md` and `docs/upgrade.md`.
