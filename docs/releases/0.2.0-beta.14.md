# TalonHound v0.2.0-beta.14

Bugfix beta: custom threat feeds now record file artifacts for the hashes they import. No database migration, no API contract changes.

All v0.2.0-beta.12 and v0.2.0-beta.13 changes are included unchanged — see the [v0.2.0-beta.12](https://github.com/spatronn/TalonHound/releases/tag/v0.2.0-beta.12) and [v0.2.0-beta.13](https://github.com/spatronn/TalonHound/releases/tag/v0.2.0-beta.13) release notes.

## Fixed

### Custom feed hash IOCs skipped file-artifact recording
In the `talonhound-integration` image, the custom threat feed sync could not load the file-artifact module it uses to record hash IOCs. The failure was caught and ignored. As a result, a custom feed that imported MD5/SHA1/SHA256 IOCs created the IOCs but no file artifact, artifact link, or custom-feed source observation, so those hashes did not join their file's alias group (SHA256 canonicalization, VirusTotal reuse across aliases, File Information).

- The integration image now resolves these imports to the same file-artifact module the built-in feed importer uses.
- The release-critical integration-image test now also checks lazy imports, so a module missing from the image is caught in CI.

Only custom feeds that import file hashes were affected; built-in feeds were not. If a custom feed imported hashes on an earlier version, run a sync of that feed after upgrading: every hash still present in the feed is recorded on the next sync, including unchanged ones.

## Compatibility
- **No database migration.** Schema is unchanged (latest migration 036).
- Only the `talonhound-integration` image changes in behavior; backend, frontend and proxy are rebuilt with the new version only.
- No API, MCP or dependency changes.
